# 架构与实现

## 1. 信号链

```
               ┌──────────── 模拟直通 ─────────────┐
外部播放器 L ──►│ CD4066 A ──► MCP41010(U5) ──┐    │
外部播放器 R ──►│ CD4066 B ──► MCP41010(U6) ──┤    │
               └──────────────────────────────┼────┼──► 加法器 ──► CD4066(U2) ──┬──► 耳机
                                              │    │                            └──► TDA2822 ──► 扬声器
麦克风 ──► 前置放大 ──► ADC1_IN0 ──► DMA ──► 固件 ──► TIM2 PWM ──► RC ──────────┘
   (偏置 1.65V)           ▲
                     TIM3 TRGO 8kHz
```

三条通路的分工决定了整个设计：

| 通路 | 处理方式 | 理由 |
|---|---|---|
| 主音乐 | 模拟直通 | 保住 20kHz 带宽与立体声；8kHz 采样会把频带砍到 4kHz |
| 人声 | 数字化 | 要做软件增益、限幅，还要和伴奏混合 |
| 控制 | SPI / GPIO / ADC | 与音频通路解耦，故障不互相传染 |

一个常见的误解是"整个系统都 8kHz 数字化再 PWM 回放"。如果那样做，音乐的高频和立体声信息
全部丢失，而且 DMA 与 CPU 负载翻倍。

## 2. 时基

STM32F103 主频 72MHz，TIM3 挂在 APB1（36MHz）。APB1 预分频不为 1 时，
定时器时钟自动翻倍回 72MHz —— 这一条经常被忽略，导致算出来差一倍。

```
f_update = f_TIM / ((PSC+1)(ARR+1))
         = 72e6 / (72 × 125)
         = 8 kHz
```

`PSC=71`（72 分频得 1MHz 计数时钟），`ARR=124`（0..124 共 125 个计数，125µs）。

PWM 载波用 TIM2：

```
f_pwm = 72e6 / (1 × 720) = 100 kHz     (PSC=0, ARR=719)
```

**这两个频率必须分开理解**：载波一直以 100kHz 跑，但 CCR 只按 8kHz 更新。
把 100kHz 当成"音频采样率"会让播放速度快 12.5 倍。

### 为什么用 TRGO 而不是中断里启动 ADC

定时器中断里有响应延迟、被其它中断抢占的风险、函数调用开销，采样间隔会抖动。
TRGO 是硬件直连：计数到 ARR → 更新事件 → 直接触发 ADC 启动转换，CPU 完全不参与。

## 3. ADC 与 DMA

```
Resolution            = 12 bit
Continuous Conversion = Disable      ← 必须关
External Trigger      = TIM3_TRGO
Trigger Edge          = Rising
Data Alignment        = Right
DMA: Peripheral→Memory, Circular, Half Word, Memory Increment = Enable
```

**为什么关掉 Continuous**：一旦打开，第一次触发后 ADC 自己不停转换，采样率就不再由 8kHz
定时器决定，而是跑到 ADC 的最快速率。

**为什么内存地址自增而外设地址不自增**：ADC_DR 是固定地址，数据要依次落到 `buf[0..255]`。

**为什么用 Half Word**：12 位结果用 `uint16_t` 存，DMA 每次搬 2 字节。

### 半缓冲 / 全缓冲

256 点循环缓冲被切成两半。DMA 写前半时 CPU 处理后半，反之亦然：

```
DMA 填 0..127  ──► 半传输中断 ──► CPU 处理 128..255
DMA 填 128..255 ──► 全传输中断 ──► CPU 处理 0..127
```

时间：256 点 = 32ms，半缓冲 128 点 = 16ms。CPU 处理一块必须在 16ms 内完成。

## 4. 数据处理

```c
s = adc - 2048;                    // 去偏置，得到 -2048..2047
s = (s * q8_gain) >> 8;            // Q8 定点增益，256 = 1.0
if (s >  2047) s =  2047;          // 限幅
if (s < -2048) s = -2048;
u = s + 2048;                      // 回偏置
ccr = (u * 720) >> 12;             // 4096 级 -> 720 级
```

**全整数运算**：Cortex-M3 没有 FPU，中断里跑 128 点浮点会直接超时。

**限幅必须在回偏置之前**。省略这一步，增益 >1 时正半周会越过 4095 后在 `uint16_t` 里回绕成小值，
听感是"噼啪"的数字爆音，比模拟削顶难听得多。测试 `t_clip_positive` / `t_clip_negative`
把这两端都钉住了。

`>> 12` 而非 `/ 4096`：编译器对无符号除法本来也会优化成移位，但写出来意图更清楚，也避免
误用了有符号除法。

## 5. PWM 重构

PWM 是 0/3.3V 的方波，低通后得到平均值：

```
V_out ≈ V_dd × duty
```

一阶 RC，`R=2.2k, C=10nF`：

```
fc = 1/(2πRC) = 7.23 kHz
```

### 纹波估算（50% 占空比）

`τ = RC = 22µs`，半周期 `T/2 = 5µs`，`k = e^{-5/22} = 0.7967`。
稳态时一个周期首尾相接：

```
V1 = k·V2,  V2 = V_dd + (V1 - V_dd)·k
=> V1 = V_dd·k/(1+k) = 1.463 V
   V2 = V1/k         = 1.837 V
   纹波 = 373 mVpp
```

仿真实测 **367 mVpp**（占空比略偏离 50%，与解析值一致）。

这个数字说明问题：麦克风信号本身才 ±280mV，纹波和信号同量级。一阶 RC 要把 100kHz
压到毫伏级，需要 `fc≈20Hz`，物理上不可能 —— 需要二阶以上有源滤波，或者提高载波频率。

## 6. 加法器与增益

反相加法器，虚地 2.5V（5V 经 R2/R3 各 100k 分压）：

```
V_out = V_bias - (R1/R8 · V_L + R1/R16 · V_mic)
```

数值（R1=20k, R8=R9=5k, R16=5k）：

| 项 | 增益 |
|---|---|
| 音乐（音量最高档，R_WB=52Ω） | 20000/(5000+52) = **3.96x** |
| 音乐（音量最低档，R_WB=9961Ω） | 20000/(5000+9961) = **1.34x** |
| 麦克风 | 20000/5000 = **4.00x** |

麦克风是单声道，同时混进左右两个加法器；音乐各走各的声道，所以立体声得以保留
（测试 `t_channel_isolation` 验证左声道单音在右声道的泄漏 < 0.1mV）。

**削顶边界**：NE5532 单电源下实际可用摆幅约 0.4~4.6V，相对虚地 ±2.1V。
音乐 0.30V×3.96 + 人声 0.28V×4 = 2.31V > 2.1V，满音量时削顶比例 0.27%。

## 7. 音量映射：为什么最后选了线性

数字电位器接成**串联变阻器**（A 端悬空，只用 B-W 两端），串在 R8 与虚地之间。
于是增益随抽头码的变化是：

```
g(code) = R1 / (R8 + R_WB(code)),  R_WB = 52 + code·9948/256
```

这条曲线本来就是双曲的、近似对数的。

教科书上"按响度幂律做三次方映射"的前提是**增益正比于抽头码**（电位器当分压器用）。
在这个电路上再叠一次三次方，等于对数量化两遍。实测：

| 映射 | 与"每档等 dB"的 RMS 偏差 | 最后 25% 行程的 dB 变化 |
|---|---|---|
| 线性 | **0.91 dB** | 3.48 dB |
| 三次方 | 1.99 dB | **0.20 dB**（几乎空行程） |

所以默认用线性（`VOLUME_MAP_LINEAR`）。三次方实现保留在 `volume_level_to_code_cubic()`，
`t_linear_beats_cubic` 把上面这张表变成了断言 —— 谁想凭直觉改回去，测试会先拦住。

但真正的问题不在这：无论怎么映射，**总行程只有 9.4dB**。

## 8. 实时性预算

| 项 | 数值 | 说明 |
|---|---|---|
| 块周期 | 16 ms | 128 点 @8kHz |
| `audio_block_process` | ≈ 21 µs | 128 次迭代 × 约 12 指令 @72MHz（量级估算） |
| 8kHz 中断本体 | ≈ 0.6 µs | 取队列 + 写 CCR1，占 0.4% CPU |
| 启动延迟 | 15.9 ms | 第一个半缓冲必须攒满才能处理 |

算力远不是瓶颈。真正的约束是**缓冲语义**：CPU 处理一块超过 16ms，DMA 就会覆盖还没被消费的数据。
仿真里把 `proc_ms` 设成 18ms 可以复现这个后果（丢块 + 持续 underrun），
`t_overrun_when_cpu_too_slow` 就是这条。

## 9. 仿真模型的有效性

这部分值得说清楚，否则"仿真过了"会被当成过度承诺。

**忠实建模的部分**

- **时基**：2.4MHz 时间步，每 300 步一个 ADC tick，与 TIM3 的 8kHz 严格对齐。
- **DMA 语义**：双缓冲 + 4 深度队列，保留"消费者取不到数据就 underrun"和"写满就丢块"两种失败模式。
- **RC 重构**：`v += α(v_in - v_out)`，`α = dt/(τ+dt)`，与连续 RC 的离散化严格等效。
- **PWM**：载波按 24 点/周期重建，占空比只在 8kHz 节拍上变化。
- **加法器**：虚地求和 + 供电轨限幅，增益随抽头阻值变化。
- **量化**：12bit ADC 与 720 级 PWM 的双重量化都在链路里。

**没有建模的部分**

- 板级噪声、电源纹波、地弹
- 麦克风的真实灵敏度与指向性
- 面包板与飞线的寄生电容（它会让 100kHz 载波漏得更多）
- 数字电位器的实际 THD 与寄生电容
- 扬声器负载对 TDA2822 输出的影响
- CubeMX 的外设配置本身

**测量方法上的一个坑**：用 FFT 单个 bin 测 5kHz 折返的残留，会被频谱泄漏污染成 −12dB 的假信号；
换成"2.5–3.5kHz 带内 RMS"才得到真实的 299mV（无滤波）与 ≈0（12 阶）。
测试与出图统一用后者。

## 10. 已知问题与修法

| 问题 | 现状 | 修法 |
|---|---|---|
| 音量行程 9.4dB | 串联变阻器 + R8=5k 分压 | 改分压接法（A 接信号、B 接地、W 取输出） |
| 100kHz 纹波 367mVpp | 一阶 RC，fc=7.2kHz | 二阶 Sallen-Key，或载波提到 300kHz 以上 |
| ADC1_IN0 分时复用 | K 歌模式暂停线控扫描（妥协） | 线控挪到独立 ADC 通道 |
| 满音量削顶 0.27% | 前级增益偏高 | R1 从 20k 降到 15k |
| 8kHz 只到 4kHz | 语音够用 | 提到 16kHz，同时重算 RC 与缓冲 |
